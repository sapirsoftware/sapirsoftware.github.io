v4 or v7?

v4v7
Contents122 random bits48-bit millisecond timestamp, then 74 random bits
Sort orderRandomCreation order
As a database primary keyWorks, but inserts land all over the index, which fragments it and slows big tablesInserts go at the end of the index, close to an auto-increment integer
RevealsNothingWhen it was created, to the millisecond
StandardRFC 9562 (was RFC 4122)RFC 9562, published May 2024

Short version: use v7 for database keys and anything you'll sort, v4 when the ID shouldn't reveal timing. Neither is a password or session token.

Generate one in code

// JavaScript (browsers and Node 19+)
crypto.randomUUID()

# Python
import uuid; uuid.uuid4()        # v7: uuid.uuid7() in Python 3.14+

-- PostgreSQL
SELECT gen_random_uuid();        -- v7: uuidv7() in PostgreSQL 18+

# Command line
uuidgen                          # macOS and most Linux
[guid]::NewGuid()                # PowerShell

What the parts mean

A UUID is 128 bits written as 32 hex digits in five groups: 8-4-4-4-12. The first digit of the third group is the version (the 4 in xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx). The first digit of the fourth group, y, is the variant: 8, 9, a or b for standard UUIDs. The all-zero 00000000-0000-0000-0000-000000000000 is the "nil" UUID, often used as a placeholder.
