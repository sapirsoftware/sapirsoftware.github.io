Hard refresh in Chrome

You changed a file, reloaded, and the browser still shows yesterday's page. Here are the shortcuts, then what to do when they aren't enough.

The shortcuts

SystemHard refresh
Windows and LinuxCtrl+Shift+R or Shift+F5
macOSCmd+Shift+R

This reloads the page and asks the server for its files again instead of reusing cached copies. It does not clear cookies, localStorage, IndexedDB or a service worker's caches.

When that isn't enough

Empty cache and hard reload

Open DevTools (F12), then right-click the reload button and choose Empty cache and hard reload. It appears only while DevTools is open.

Disable cache while you work

DevTools → Network → tick Disable cache. It applies while DevTools stays open, which is the setting most developers want all day.

A service worker is serving the old files

DevTools → Application → Service Workers. Tick Update on reload, or press Unregister and reload. This is the usual reason a hard refresh "doesn't work" on a modern app.

A CDN or proxy is holding the file

Your browser isn't the only cache. Check the response headers for Cache-Control, Age and any CDN header. Fix it at the source with sensible headers:

Cache-Control: no-store            # never cache (HTML you always want fresh)
Cache-Control: max-age=31536000, immutable   # hashed asset files

Quick answers

  • Incognito starts with an empty cache and no service workers, which makes it a fast sanity check.
  • Ctrl+F5 behaves like a hard refresh in Chrome; in some other browsers it is the same as a normal reload.
  • Still stale? Confirm you're hitting the server you think: check the address, any proxy, and the Age response header.
